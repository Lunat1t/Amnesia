## Внутреннее свидетельство и ограничения Galaxy

- [Контролируемый аудит v1](../../../reports/experience-transfer-v1/controlled-audit.json): при 5000 токенах B прошёл с Experience, с обычным контекстом и OFF; доставка эпизода подтверждена, improvement не установлен. Это legacy retrieval, не compaction внешнего runtime. [Тест continuity](../../../source-snapshots/tests/test_experience_continuity.py) уже проверяет retraction и invalidation кэша; очередное предложение «добавить отзыв» без нового failure mode было бы дубликатом.

Код и артефакты сверены read-only; тесты и coding-benchmarks в этом исследовательском запуске не выполнялись. [Roadmap](../../galaxy-v5-roadmap.md), [foundation](../../architecture/foundation.md), [current state](../../architecture/current-state.md) и карточки [01](01-current-galaxy.md), [05](05-product-validation.md), [08](08-operation-amnesia-radar.md) поддерживают границы полномочий и требование проверять outcome. ## Общие требования к четырём минимальным экспериментам

Для каждого пилота заранее заморозить 8 пар coding-задач, две повторности, порядок условий, одинаковые модель/runtime, исходный snapshot, tools, бюджет и независимый evaluator. Это диагностический пилот, недостаточный для общего заявления об эффективности. Сначала подобрать задачи с несатурированным control; не наращивать прежнюю лёгкую синтетику ради положительного результата. Context controls должны совпадать вне исследуемого вмешательства; генерация памяти видит только Task A/pre-fix evidence, не gold patch или hidden checks Task B. Не исключать no-edit, overflow и неудачи из общего знаменателя; infra failures отмечать отдельно по заранее заданному правилу.

Для каждой ветки считать verified task success и regressions; stale-use после подтверждённого изменения и false suppression; долю утверждений с правильными source/run/hash и областью применимости; wall time, время подготовки/извлечения/компиляции, повторные чтения, input/output/cached tokens и полную стоимость. Extraction и retrieval входят в overhead. Стоимость брать из доступных фактических usage и тарифа зафиксированной даты; если их нет, cost = unavailable, а не вывод из общего числа токенов. Сохранить точный delivered package и evidence hashes. Path match/доставка сами по себе не доказывают использование или причинную пользу.

## 1. Документация полезна, если добавляет отсутствующую информацию

**Внешний источник:** Md Shohel Arman и Igor Molybog, [Compact Documentation for Coding Agents: A Benchmark, an Optimizer, and Why It Does Not Transfer](https://arxiv.org/abs/2609.31587v1), 2026-09-25; [полный текст](https://arxiv.org/html/2609.31587v1), §§3, 7–8; [репозиторий авторов](https://github.com/haw-ai-i/roundtrip). Статус: arXiv preprint; независимая репликация не проверена. GitHub просмотрен как указатель на воспроизводимость, commit не зафиксирован и код не запускался.

**Что подтверждает источник:** авторы сообщают отрицательный downstream результат при доступном исходнике, хотя оптимизация описаний улучшает roundtrip. В контролируемых примерах помогает контракт, отсутствующий в коде. Это граница их эксперимента, не универсальное отсутствие пользы документации. Ограничения: небольшие roundtrip fixtures; крупный downstream run на одной экономичной модели; сильные модели проверены на django subsets; paired comparison исключает часть no-edit, поэтому attrition неслучайна. Объявленный авторами positive control не устраняет эти ограничения.

**Гипотеза Galaxy:** отдельно проверять память о намерении/ограничении, которого нет в текущих доступных файлах, и summary этих же файлов. Возможное отличие — сохранение подтверждённой причины решения сверх repo baseline. **Неизвестно:** есть ли такие задачи у пользователей достаточно часто и можно ли извлечь причину без ошибки.

**Контргипотеза/вред:** полезное «why» уже находится в issue, тестах или AGENTS.md; дополнительная запись отвлекает, провоцирует переписывание либо переносит неверный контракт из другой задачи.

**Минимальный тест:** в четырёх парах нужные сведения уже доступны в repo/issue, в четырёх только в подтверждённом source episode A. Во всех ветках исходники доступны. Сравнить A: repo/context-only; B: равный по бюджету source summary; C: evidence-linked decision/constraint memory. Missing-information positive control моделирует документированную утрату handoff, не искусственное скрытие кода. Добавить подтверждённо obsolete вариант записи; свежесть и происхождение оценивать по общему протоколу. Основной falsifier — C не даёт преимущества именно на missing-information случаях и не сокращает полную стоимость при равном исходе. Остановить расширение при таком результате пилота; любое применение неподтверждённого/чужого контракта требует разбора до следующих запусков. Не объявлять общий null по восьми парам.

**Решение:** исследовать первым как различение добавочной информации и её дублирования; не создавать генератор wiki.

## 2. Выдержки из оригинала против повторного пересказа

**Внешний источник:** Trang Nguyen, Eulrang Cho, Bingqing Chen и Tim Dettmers, [CliffCompaction: Cost-Efficient Compaction for Long-Horizon Coding Agents](https://arxiv.org/abs/2609.26779v1), 2026-09-22; [полный текст](https://arxiv.org/html/2609.26779v1), §§2, 8; [репозиторий авторов](https://github.com/nguyenvuthientrang/cliffcompaction). Статус: arXiv preprint, авторская реализация, без нашей репликации; GitHub main изменяемый, commit не зафиксирован.

**Что подтверждает источник:** метод удаляет/обрезает исходный текст вместо перефразирования и повторно работает с оригиналом, ограничивая накопление искажений. Авторы сообщают экономию на своих длинных coding runs. Они не сравнивают метод с внешними memory stores; эффект зависит от scaffold и длины задачи. README описывает API proxy и требует совместимости с историей runtime, поэтому наличие интеграции в repo не доказывает пригодность для Galaxy MCP.

**Гипотеза Galaxy:** при подготовке compact Experience точные source excerpts с hashes могут сохранить literals, условия и результат команды лучше цепочки summary-of-summary. **Неизвестно:** не потеряется ли причинная связь при удалении; выиграет ли следующий Task B. Это вопрос об артефакте Context/Experience, не предложение менять compactor Codex.

**Контргипотеза/вред:** важное evidence часто находится в длинном tool output; механическое удаление уберёт его. Сохранённая дословно ошибочная мысль агента останется ошибочной. Совпадение текста с источником не доказывает истинность.

**Минимальный тест:** одни Task A traces преобразовать в A: текущий compact Experience; B: повторный пересказ на каждом из трёх handoff; C: каждый handoff выбирает excerpts из неизменяемого оригинала. B — stress control, не описание нынешнего Galaxy. Бюджет delivered text одинаков, отбор не видит B; набор содержит точную команду/путь/условие и длинный значимый output. В общие outcome/cost/freshness/provenance метрики добавить утрату literals и смысловых qualifiers после 1/3/5 преобразований. Falsifier: C не снижает искажение или сохраняет текст, но ухудшает B outcome/полную стоимость. Остановить после заранее заданного пилота при этом результате; потеря обязательного evidence блокирует расширение. Не устанавливать proxy и не менять runtime.

**Решение:** небольшой offline replay артефактов после стабильного source episode; не новый обязательный compaction слой.

## 3. Разные требования к сохранению правил и истории

**Более ранний первоисточник:** Saber Zerhoudi, Jelena Mitrović и Michael Granitzer, [The Compaction Cliff in Long-Running AI Agent Memory](https://arxiv.org/abs/2608.22752v1), 2026-08-24, вне 30-дневного окна; [полный текст](https://arxiv.org/html/2608.22752v1), §§3–5; [авторский repo Knowledge Triage](https://github.com/searchsim-org/cikm26-knowledge-triage). Статус: доступная авторская arXiv-версия указывает CIKM 2026 и [ACM DOI](https://doi.org/10.1145/3799682.3840567); статус финальной публикации/рецензирования независимо у издателя в этом запуске не подтверждён. Не выдавать за свежую сентябрьскую работу.

**Что подтверждает источник:** авторы наблюдают потерю правил при повторном type-blind compaction и предлагают раздельные retention policies. Их гарантия зависит от полноты классификации и выполнимого бюджета; сохранение записи не гарантирует соблюдение моделью. Downstream задачи медицинские и customer-service, не coding. Human agreement хуже для пяти типов, чем для constraint split. Это механизм для проверки, а не доказательство безопасности продукта.

**Гипотеза Galaxy:** сохранять точные подтверждённые ограничения задачи вместе с областью действия, а завершённую историю сжимать сильнее. Отличие от карточки 09: здесь исследуется fidelity при нескольких преобразованиях, а не определение supersession. **Неизвестно:** где проходит граница rule/fact/procedure в реальном coding trace и сколько полезного контекста вытеснит pinning.

**Контргипотеза/вред:** classifier объявит hard rule предположение, старое ограничение или текст из недоверенного tool output; слишком много pinned items вытеснят источник решения. Сохранённая устаревшая инструкция может вредить сильнее пересказа.

**Минимальный тест:** одинаковые traces с подтверждёнными ограничениями, императивными и декларативными формулировками, отменённым правилом и instruction-like distractor. A: обычный summary; B: ручная независимая разметка и точные in-scope excerpts; C: модельная разметка того же материала. B отделяет benefit retention от ошибки classifier. Через 1/3/5 преобразований считать не только recall правил, но проверенные действия/patch и qualifier preservation; freshness/provenance/cost — по общему протоколу. Falsifier: даже B не улучшает соблюдение/outcome или вытесняет необходимое evidence; C не имеет оснований внедрять при classifier misses/false pins. Любое превращение недоверенного/отменённого текста в действующее правило блокирует расширение и требует разбора. Если обязательный пакет не помещается, пометить budget infeasible, не терять правила молча.

**Решение:** исследовать preservation как отдельный диагностический тест; не активировать правила или SkillCandidate.

## 4. Доступная память может остаться невостребованной

**Внешний источник:** Run-Ze Fan и соавторы (Zihao Zhang, Simin Ma, Yebowen Hu, Shouju Wang, Kaiqiang Song, Fei Liu, Hamed Zamani, Xiaoyang Wang), [An Empirical Study of Harness Design for Coding Agents](https://arxiv.org/abs/2609.20804v1), 2026-09-17; [полный текст](https://arxiv.org/html/2609.20804v1), §3.2, Limitations, §9.6. Статус: arXiv preprint; авторские 176 matched settings, не независимая репликация.

**Что подтверждает источник:** добавление recall_event к elision редко используется и не даёт устойчивого accuracy gain в их matched comparison; context management прежде всего предотвращает overflow при малом окне. Ограничения: один run на задачу, конкретные threshold policies, Nemotron/Mistral и два benchmark-а, неполный factorial design. Это не эксперимент с Codex MCP get_context: интерфейс и тип возвращаемых данных отличаются.

**Гипотеза Galaxy:** цепочку eligible → retrieved → delivered → used → verified outcome нужно диагностировать по режиму и бюджету; архив и endpoint не обеспечивают использование. Новое относительно provenance retrieval leads — отделить пользу доставки от способности внешнего агента запросить её при давлении контекста. **Неизвестно:** возникает ли аналогичная недоставка/неиспользование с текущим MCP.

**Контргипотеза/вред:** запрос памяти просто не нужен, потому что repo содержит всё; принудительная доставка добавит шум и tokens. Низкая частота вызовов может означать достаточный контекст, а не дефект discoverability.

**Минимальный тест:** на тех же real Task A→B pairs сравнить A: context-only; B: существующий native retrieval path с доступным episode; C: forced exposure того же episode в имеющемся экспериментальном runner. Повторить при двух заранее выбранных budgets, не вводить recall tool или event system. Сохранить actual get_context calls, eligible/retrieved/delivered и evidence использования: корректное воспроизведение конкретного решения плюс независимый outcome, а не одно открытие файла. Добавить irrelevant/obsolete advice controls. Outcome, stale-use, provenance, время и полная стоимость обязательны; меньший бюджет не должен менять остальные параметры. Если C не помогает, гипотеза «проблема только в доставке» отвергается для пилота; если C помогает, а B не доставляет, сначала локализовать потерю бюджета/отбора/вызова, не назначать причину заранее. Остановить расширение при отсутствии пользы C или росте harmful advice; не строить дополнительную интеграцию ради числа вызовов.

**Решение:** диагностика существующего Codex MCP/Context пути, без нового runtime и orchestration.
