# Galaxy 3.2.0-alpha.1 — Attention Engine

## Зачем нужен этот выпуск

В версии 3.0 контекст проекта стал явным. В версии 3.1 он стал актуальным и прогностическим. Версия 3.2 меняет вопрос:

> Какие файлы подходят для этой задачи?

на вопрос:

> Какой минимальный, насыщенный свидетельствами обзор проекта даст исполнителю достаточно информации, не перегружая его посторонним контекстом?

## Новая подсистема

`galaxy_core/attention/`

Pipeline:

```text
task
 ↓
wide retrieval
 ├─ BM25/content
 ├─ lexical path/symbol
 └─ portable semantic similarity
 ↓
structural expansion
 ├─ dependency graph
 └─ Future Graph
 ↓
gatekeeper
 ↓
evidence extraction
 ↓
adaptive budget packer
 ↓
selected context
```

## Принципы проектирования

- По умолчанию работает без сети и дополнительных зависимостей.
- Не требует сервиса векторного поиска.
- При обычном поиске нет скрытых внешних вызовов LLM.
- Для небольших проектов можно использовать ограниченный полный контекст.
- Для крупных проектов применяется гибридный механизм внимания.
- Вероятностная фильтрация — необязательное ограниченное уточнение, а не источник полномочий.
- Диагностика поиска обозначается как эвристическая.

## CLI

```bash
python galaxy.py attention-build "task" --root /repo --project demo
python galaxy.py context-build "task" --root /repo --project demo --budget-tokens 0
```

Параметр `--budget-tokens 0` включает адаптивное распределение бюджета.

## Добавленные тесты

Регрессионные проверки версии 3.2 подтверждают, что:

1. релевантные свидетельства можно извлечь из середины длинного файла;
2. расширение по зависимостям/Future Graph может включать связанные тесты;
3. действительно небольшой проект может использовать ограниченный полный контекст;
4. адаптивный бюджет различает локальную и архитектурную работу;
5. диагностика Attention Engine и свидетельства появляются в итоговых Context Packets.

## Известные ограничения alpha-версии

- По умолчанию семантическая оценка использует переносимый хешированный embedder Galaxy, а не нейросетевую модель векторизации кода.
- BM25 пересобирается в памяти при каждом запуске механизма внимания; постоянные поисковые индексы — будущая оптимизация.
- Свидетельства извлекаются по окну строк; анализ блоков AST и потока данных пока не поддерживается.
- Качество графа ограничено текущими извлекателями зависимостей World Model.
- Сигналы качества внимания — внутренняя диагностика, а не проверенные бенчмарками метрики правильности.
- Поиск на уровне выполнения, API, базы данных и сервиса пока не является основной возможностью.
